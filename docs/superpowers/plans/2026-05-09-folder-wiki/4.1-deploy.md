# Slice 4.1 — Deploy

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Production-deploy `apps/api` to Cloudflare Workers (with D1, R2, KV, Durable Objects, Cron, secrets) and `apps/web` to its target per ADR-0002 (Workers Static Assets, per `0001` Slice 5). Confirm a public URL renders the live demo.

**Architecture:** No code. Wrangler-driven deploys. Secrets from Infisical → `wrangler secret bulk`. Static asset serving for `apps/web` on the same Worker as `apps/api` (per ADR-0002).

## Task 1: Production wrangler.toml

**Files:**
- Modify: `apps/api/wrangler.toml`

- [ ] **Step 1: Add production environment**

```toml
# apps/api/wrangler.toml (production block)
[env.prod]
name = "tenex-api"

[env.prod.vars]
ENVIRONMENT = "production"

[[env.prod.d1_databases]]
binding = "DB"
database_name = "tenex"
database_id = "<production-d1-id>"

[[env.prod.kv_namespaces]]
binding = "CACHE"
id = "<production-kv-id>"

[[env.prod.r2_buckets]]
binding = "STORAGE"
bucket_name = "tenex"

[[env.prod.durable_objects.bindings]]
name = "COMPILE_RUN"
class_name = "CompileRunDO"

[[env.prod.durable_objects.bindings]]
name = "CONVERSATION"
class_name = "ConversationDO"

[[env.prod.durable_objects.bindings]]
name = "LINT_RUN"
class_name = "LintRunDO"

[env.prod.triggers]
crons = ["0 6 * * *"]
```

- [ ] **Step 2: Provision production resources**

```bash
bunx wrangler d1 create tenex --location=eeur
bunx wrangler kv namespace create CACHE
bunx wrangler r2 bucket create tenex
```

Paste the IDs into `wrangler.toml`. Apply migrations:

```bash
bunx wrangler d1 migrations apply tenex --remote --env=prod \
  --file=packages/domains/ingestion/src/infrastructure/migrations/001_init.sql
bunx wrangler d1 migrations apply tenex --remote --env=prod \
  --file=packages/domains/wiki/src/infrastructure/migrations/001_init.sql
bunx wrangler d1 migrations apply tenex --remote --env=prod \
  --file=packages/domains/chat/src/infrastructure/migrations/001_init.sql
bunx wrangler d1 migrations apply tenex --remote --env=prod \
  --file=packages/domains/verification/src/infrastructure/migrations/001_init.sql
```

(`d1 migrations apply` doesn't take `--file` directly — use `d1 execute --remote --file=<sql>` per file. Adjust accordingly.)

- [ ] **Step 3: Push secrets**

```bash
bun --filter @app/api run secrets:push
```

This runs `bunx infisical export --env=prod --path=/apps/api --format=dotenv | wrangler secret bulk` (already wired in `apps/api/package.json`). Verify with:

```bash
bunx wrangler secret list --env=prod
```

Expected: `GOOGLE_OAUTH_CLIENT_ID`, `GOOGLE_OAUTH_CLIENT_SECRET`, `GOOGLE_OAUTH_REDIRECT`, `OAUTH_TOKEN_KEY_BASE64`, `ANTHROPIC_API_KEY` all present.

- [ ] **Step 4: Commit**

```bash
git add apps/api/wrangler.toml
git commit -m "chore(4.1): production wrangler env + DO + cron + bindings"
```

## Task 2: Static asset serving for apps/web (per ADR-0002)

**Files:**
- Modify: `apps/api/wrangler.toml` (add `assets` binding)
- Modify: `apps/web/package.json` (`build` outputs to `dist/`)
- Modify: `apps/api/src/index.ts` (fall through to assets on 404)

- [ ] **Step 1: Build apps/web**

```bash
VITE_USE_MOCKS=0 VITE_API_URL=https://tenex-api.<workers-domain>.workers.dev \
  bun --filter @app/web run build
```

Output lands at `apps/web/dist/`.

- [ ] **Step 2: Add `assets` binding**

```toml
# apps/api/wrangler.toml
[env.prod.assets]
directory = "../web/dist"
not_found_handling = "single-page-application"
binding = "ASSETS"
```

- [ ] **Step 3: Adjust apps/api/src/index.ts**

The existing `app.get('/', ...)` returns "tenex api" — remove it. Wrangler's static-asset binding handles the root + SPA fallthrough automatically when no Worker route matches. Just make sure `/rpc/*` and `/r2/*` routes are mounted before any catch-all.

- [ ] **Step 4: Deploy**

```bash
bun --filter @app/api run deploy --env=prod
```

Expected: `wrangler deploy` succeeds; output shows the `tenex-api.<workers-domain>.workers.dev` URL.

- [ ] **Step 5: Smoke test the live URL**

```bash
curl -s https://tenex-api.<workers-domain>.workers.dev/rpc/core/health | jq
```
Expected: `{ "status": "ok", "timestamp": "..." }`.

Open the URL in a browser. Expected: the SPA shell loads, the folder picker renders, dark mode follows OS pref.

- [ ] **Step 6: Commit + tag**

```bash
git add apps/api/wrangler.toml apps/api/src/index.ts apps/web/package.json
git commit -m "chore(4.1): static-asset SPA serving + production deploy"
git tag deploy-prod-$(date +%Y%m%d-%H%M)
git push --tags
```

## Task 3: Drive OAuth callback URL update

The OAuth client created in 1.A points at `localhost`. Update it to the production URL.

- [ ] **Step 1: Cloud Console**

In Google Cloud Console → Credentials → OAuth 2.0 Client → Authorized redirect URIs, add:
- `https://tenex-api.<workers-domain>.workers.dev/rpc/ingestion/authCallback`

- [ ] **Step 2: Update Infisical secret**

```bash
bunx infisical secrets set --env=prod --path=/apps/api GOOGLE_OAUTH_REDIRECT=https://tenex-api.<workers-domain>.workers.dev/rpc/ingestion/authCallback
bun --filter @app/api run secrets:push
```

- [ ] **Step 3: Test the auth flow against the live deployment**

```bash
curl -X POST https://tenex-api.<workers-domain>.workers.dev/rpc/ingestion/authStart | jq -r .authorizationUrl | xargs open
```

Open the URL, consent, and confirm the `userId` row lands in the production D1.

- [ ] **Step 4: Seed the production demo folder**

Manually call `registerFolder` against the production demo folder ID, run a one-shot `ingestFolder` + `startCompile` to pre-warm the demo wiki so the live URL is "ready to demo" rather than empty.

```bash
DEMO_FOLDER=<drive-folder-id>
curl -s -X POST https://tenex-api.<workers-domain>.workers.dev/rpc/ingestion/registerFolder \
  -H 'content-type: application/json' \
  -d "{\"driveFolderId\":\"$DEMO_FOLDER\",\"name\":\"Halcyon Labs board\"}"
```

(Capture the returned `folderId`. Stash in `docs/projects/folder-wiki/demo-folder.md`.)

```bash
FOLDER=<folderId from previous step>
curl -s -X POST https://tenex-api.<workers-domain>.workers.dev/rpc/ingestion/ingestFolder \
  -H 'content-type: application/json' -d "{\"folderId\":\"$FOLDER\"}"
curl -s -X POST https://tenex-api.<workers-domain>.workers.dev/rpc/wiki/startCompile \
  -H 'content-type: application/json' -d "{\"folderId\":\"$FOLDER\"}"
```

Wait for `CompileFinished`, then open `https://tenex-api.<workers-domain>.workers.dev/wiki/<wikiId>` in a browser. Expected: the magazine WikiPages render against real data.

- [ ] **Step 5: Commit demo folder ID**

```bash
git add docs/projects/folder-wiki/demo-folder.md
git commit -m "docs(4.1): demo folder live IDs"
```

# Deploy

## API + frontend (production)

```bash
# 1. Build the SPA
VITE_USE_MOCKS=0 VITE_API_URL=https://tenex-api.<workers-domain>.workers.dev \
  bun --filter @app/web run build

bun --filter @app/api run secrets:push

## Apply a new D1 migration

```bash
bunx wrangler d1 execute tenex --remote --env=prod \
  --file=packages/domains/<context>/src/infrastructure/migrations/<NNN>_<name>.sql
```

## Roll back

`wrangler` supports rollback via the dashboard. For DB rollbacks, hand-author the inverse migration; D1 is point-in-time only as of 2026-05.
