# wiki — ubiquitous language (draft)

Bounded context for the compiled, interlinked knowledge graph derived from
Sources. The wiki is the model that the chat and verification contexts read
against.

## Aggregate

`Wiki` is the aggregate root, scoped to one Folder. A Wiki has a `WikiSchema`
declaring its typed `PageType`s and `Relation`s; contains many `WikiPage`s;
pages link to each other via `Backlink`s; pages cite Sources via `Citation`s
attached to `Claim`s.

## Terms

| Term | Definition | Notes |
|---|---|---|
| Wiki | The aggregate of all WikiPages produced from a Folder. One Wiki per Folder. | Aggregate root. Has a `WikiSchema`. |
| WikiSchema | Per-Wiki value object declaring the typed `PageType`s and `Relation`s for this domain. Generated by the SchemaInferrer agent. | Third-leap addition. |
| PageType | A domain-specific classification of `ConceptPage`s (e.g. "Decision", "Metric", "Person"). String-typed within a closed set per WikiSchema. | Third-leap addition. |
| Relation | A typed `Backlink` declared in the WikiSchema (e.g. `Decision-DecidedAt-Meeting`). | Third-leap addition. |
| WikiPage | A single markdown page in the wiki. One of four subtypes. | Distinct from `Page` in ingestion context. |
| ConceptPage | A WikiPage about a single entity. Has a `pageType` (e.g. "Decision"). | Subtype. |
| SummaryPage | A per-Source WikiPage synthesizing what that Source says. | Subtype. |
| AnswerPage | A WikiPage filed back from chat Q&A; preserves a hard question and answer. | Subtype. Filed via AnswerProduced event from chat. |
| IndexPage | Auto-generated WikiPage that lists all ConceptPages of a given PageType. | Subtype. Third-leap addition. |
| Backlink | A directed reference from one WikiPage to another, optionally typed by a `Relation`. | |
| Citation | A `(Span, label)` pair attached to a Claim in a WikiPage. Every Claim is cited. | |
| Claim | A verifiable assertion in a WikiPage. The atomic unit the verification context audits. | Same identity as `Claim` in verification. |
| Compile | The operation that takes a Folder + its Sources and produces (or updates) a Wiki. | |
| CompileRun | A single invocation of Compile. Has status, started_at, ended_at, schema_inferred_at, emits CompileEvents. | |
| CompileEvent | A streamed event during a CompileRun. e.g. SchemaInferred, SourceIngested, PageDrafted, BacklinkResolved, IndexBuilt, CompileFinished. Drives the live trace UI. | |
| Compiler | The composite agent performing Compile: SchemaInferrer + Planner + Researchers + Drafter + Linker + IndexBuilder. | Application-layer concept. |

## Banned synonyms

| Don't write | Write |
|---|---|
| embedding / vector / index | (avoid) — we don't vector-index the wiki; agentic search reads it directly |
| chunk | Span (and Spans live on Sources, not WikiPages) |
| page (alone) | WikiPage |
| section | WikiPage or Outline section (per context) |
| Source (as the cited thing) | CitedSource (when standalone) or Citation (the relationship) |
| build | Compile |
| graph | Wiki (the whole) or Backlinks (the link structure) |
| schema (alone, in code) | WikiSchema |
| type (when referring to PageType) | PageType |

## Cross-context notes

- `Source` here is citation provenance, not the raw fetched record (which lives in ingestion). Prefer `Citation.source` or `CitedSource` in code.
- `Page` always means `WikiPage`; ingestion's PDF page integer is different.
- `Claim` is the join point with verification — same identity, different concerns (wiki structures it, verification audits it).
- `WikiSchema` surfaces to the UI via the `SchemaInferred` event during compile theater.
